# Spotify Playlist MCP

Three FastMCP tools over stdio. The server uses the existing local OAuth login.
Credentials and token files are never included in the MCP configuration.

## Install and start

From `week2/`, using Python 3.10 or newer supported by the pinned FastMCP release:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
python3 spotify_auth.py --configure
python3 spotify_auth.py --login
python3 spotify_auth.py --check
```

The single server start command is:

```sh
.venv/bin/python server.py
```

It waits for MCP messages over stdin/stdout. No web server or additional hosting
is required. Only the separate `--login` command opens a browser. Credentials
are loaded from environment variables, falling back to `.env` beside the code.

## Tools

| Tool | Purpose | Identifier contract |
|---|---|---|
| `search_tracks(query, limit=5, offset=0)` | Find tracks, 1–10 results per page | Returns `uri` values for `track_uris` |
| `list_my_playlists(limit=20, offset=0)` | List playlists, including followed ones | Returns `id` values for `playlist_id` |
| `add_tracks_to_playlist(playlist_id, track_uris, dry_run=True)` | Preview or append 1–20 tracks | Accepts IDs/URIs from the read tools |

Both read tools return `next_offset` when another page is available. Search
results omit album artwork and other unused provider data. Tool annotations
identify the two readers and the non-idempotent writer.

The writer supports only private playlists owned by the signed-in user, matching
the requested `playlist-read-private` and `playlist-modify-private` scopes. Create
an owned private test playlist in Spotify before the demo. A preview verifies
the destination and returns its name and the requested track URIs without
posting any changes. Commit only after approving the exact preview, by setting
`dry_run=false`. Repeating a commit can add tracks again. Duplicate URIs within
one request are rejected; existing playlist contents are not deduplicated.

Expected provider/authentication failures return `ok=false` with `error.code`,
`message`, `retryable`, and `next_step`; rate limits include the retry delay when
Spotify supplies one. Invalid tool arguments are rejected by the MCP framework
before API requests. An uncertain write result asks you to inspect the playlist
instead of automatically retrying. Token expiry triggers silent refresh; revoked
authorization returns an instruction to run `spotify_auth.py --login` separately.

## Connect Claude Code

From `week2/`, register the server using absolute paths:

```sh
claude mcp add --scope local --transport stdio spotify-week2 -- "$PWD/.venv/bin/python" "$PWD/server.py"
claude mcp get spotify-week2
```

`.mcp.json.example` provides the shareable configuration with placeholder paths.
For project-scoped configuration instead, replace both placeholders with this
machine's paths and save it as `.mcp.json`. That real file is gitignored. Run
Claude Code from `week2/` and restart an already-running chat to load new tools.

Example prompt to enter in Claude Code:

> Find Nights by Frank Ocean, locate my MCP Test playlist, and preview adding
> the track. Show the song and destination before making any change.

Review the preview, then explicitly approve it if you want to perform the write.
For a failure demo, use a nonexistent, correctly formatted 22-character playlist
ID with `dry_run=true`, inspect the returned error, then recover by listing the
real playlists. Capture the actual prompt, arguments, results, and any tool
refinement for your own writeup; a programmatic smoke test is not an agent chat.

## Tests

```sh
.venv/bin/python -m unittest discover -s tests -v
```

These tests need no Spotify account. OAuth and HTTP tests use fake responses;
protocol tests start a separate stdio server with an injected fake API and use
the MCP client to discover and call the real tools. They verify input schemas,
output shaping, chaining, previews versus commits, errors, and session recovery.

To verify the real OAuth refresh without waiting for expiry:

```sh
python3 spotify_auth.py --refresh
python3 spotify_auth.py --check
```

Keep `.env`, `.spotify-tokens.json`, `.mcp.json`, and `.venv/` untracked. Your
assignment `writeup.md` is separate and is not generated by these scripts.
